## Slide 1: The problem

**Our social infrastructure is built to extract, not serve.**

- Data fragmented across incompatible silos — no interoperability, no exit
- Interfaces fixed and uniform — no adaptation to community needs
- Innovation siloed — duplicated effort, zero-sum competition for network effects
- Incentives misaligned — the systems that scale are the ones optimised for control

**The result:** collective intelligence constrained at exactly the moment we need it most.

---

## Slide 2: The pattern

**The same problem appears at every layer of the stack. So does the solution.**

```
┌─────────────────────────────────────────────────┐
│         Synergy  —  value & signal layer        │
├─────────────────────────────────────────────────┤
│           WE  —  interface layer                │
├─────────────────────────────────────────────────┤
│         AD4M  —  data & meaning layer           │
├─────────────────────────────────────────────────┤
│      Any backend · protocol · UI framework      │
└─────────────────────────────────────────────────┘
```

One architectural move, repeated three times:
introduce a spanning meta-layer that enables **radical diversity at the base** and **interoperability at the top** — with no chokepoint in between.

---

## Slide 3: The urgency

**AI is accelerating our path toward one of two futures.**

- Coordination is necessary for survival — but it can take healthy or pathological forms
- AI amplifies whatever social substrate it runs on: extractive systems become more extractive; open ones become more powerful
- The infrastructure for a healthy alternative needs to exist _before_ the window closes

This is why we're building now.

## Slide 4: AD4M — the data spanning layer

**App developers are forced to pick one backend. All their users inherit that choice.**

```
   ┌──────────┐   ┌──────────────┐   ┌──────────┐
   │   Flux   │   │ Any AD4M App │   │ Your App │
   └─────┬────┘   └──────┬───────┘   └────┬─────┘
         └───────────────┼────────────────┘
                         ▼
         ┌───────────────────────────────────┐
         │         AD4M  Spanning  Layer     │
         │   Perspectives · SPARQL · SHACL   │
         │            DID Identity           │
         └───────────────────────────────────┘
                         │
         ┌───────────────┼───────────────────┐
         ▼               ▼                   ▼
   ┌───────────┐   ┌──────┐   ┌──────────┐   ┌──────────┐
   │ Holochain │   │ IPFS │   │Blockchain│   │ Local DB │
   └───────────┘   └──────┘   └──────────┘   └──────────┘
```

- Communities choose their own storage — apps don't need to care
- Data is portable: switch apps without losing your history
- Interoperability baked in: incompatible backends, compatible data
- AI agents participate as native peers — same identity, same graph, same neighbourhoods

_Built on Holochain. Open source. MCP server included._

## Slide 5: WE — the interface spanning layer

**Every app forces one interface on every community. WE makes interfaces composable.**

```
  ┌─────────────────────┐
  │  Module Marketplace │ ──┐
  └─────────────────────┘   │    ┌─────────────┐    ┌─────────────────┐    ┌────────────────┐
                            ├──▶ │ JSON Schema │───▶│ Schema Renderer │───▶│ Live Interface │
  ┌─────────────────────┐   │    └─────────────┘    └─────────────────┘    └────────────────┘
  │    AI / No-Code     │ ──┘
  └─────────────────────┘
```

- Interfaces described as JSON — safe to share, fork, remix at runtime
- Open module marketplace: contribute once, use across all WE apps
- Communities adapt their tools to their specific needs without fragmenting
- AI can generate and modify interfaces directly — no-code is native

_Framework-agnostic. SolidJS default, React/Vue/Svelte planned._

- **Synergy Fuel (SF):** the universal currency that holds the top of the stack while community-specific economies grow into place
